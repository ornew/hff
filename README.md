HFF is a small, type-safe filter language for people querying your service.
Combine conditions, search nested data, and filter collections in expressions
you can read at a glance. Choose the features your service exposes, with one
language designed for local evaluation and translation to backends such as SQL.

```hff
name="Alice" age>=18
labels.app="api" labels.env="production"
status>=500 latency_ms>1000
status="open" priority:in("high","urgent")
assignee!.email~"@example\\.com$"
items:any(item=>item.price*item.quantity>=100)
```

## Why HFF

- **Built for Humans.** Write compact conditions with familiar comparisons,
  spaces for AND, and methods for common filtering tasks. The syntax prioritizes
  how people read and write queries.
- **Portable Across Backends.** Use the same syntax and semantics for local
  evaluation and translation to SQL or other processing systems. Backend
  adapters map the language to each target without changing the query grammar.
- **Lightweight and Flexible.** Keep the runtime small and portable. Extend
  typed methods and backend adapters to fit different environments and service
  requirements.
- **Pure and Type-Safe.** Check variables and operations against a schema before
  evaluation. Filters have no side effects, and null-safe rules handle missing
  values without exception-handling expressions.
- **Configurable Capabilities.** Choose the operators and methods your service
  supports. The syntax stays fixed; unavailable features are rejected during
  compilation.
- **Ready to Use.** Supply a schema and capability set to a configurable engine.
  Typed Go parsing generated by PEGO, compilation, and execution form an
  integrated filter interface for your service.

HFF is deliberately a filter language, not a complete programming language.
Queries must depend on service data: `age+10<20` is a filter, while `1+1`,
`10<20`, and `10<age` are rejected.

## Related languages

[AIP-160 filtering](https://google.aip.dev/160) addresses human-written service
filters. HFF aims to cover needs beyond that model, including arithmetic,
list indexing, and receiver methods. HFF uses AND-before-OR precedence, unlike
AIP-160's OR-before-AND rule.

[CEL](https://cel.dev/) is a portable, safe expression language for embedding in
applications. HFF places its emphasis on quickly written filter queries,
service-specific capability selection, and translation to arbitrary backends
alongside its own runtime.

## Syntax and parser

HFF syntax is defined in [PEGO](https://github.com/ornew/pego), with a typed Go
parser generated from the grammar. The syntax-only parser is currently internal
to this module; applications do not yet have a public parse-only API. The same
grammar is used for every capability configuration. PEGO is a development-time
parser generator, not a requirement to compile grammars at runtime.

## Specification

This repository provides immutable values, schemas, capabilities, validated
input, common query compilation, core local evaluation, scalar/string methods,
and list/object methods and collection callbacks. Base64 conversion methods are
also available locally. Additional JSON/stringification methods, extension
registration, and SQL translation are not yet available. Start with the
[Go guides](docs/guides/README.md), including the
[local evaluation guide](docs/guides/local-evaluation.md),
[scalar/string method guide](docs/guides/scalar-methods.md), and
[collections guide](docs/guides/collections.md) and
[callback guide](docs/guides/callbacks.md).

Read the [language specification](spec/README.md), beginning with
[syntax](spec/syntax.md), [types and schemas](spec/types.md), and
[evaluation](spec/evaluation.md). The [method catalog](spec/methods.md) describes
the configurable library; [capabilities and backends](spec/capabilities.md)
describe integration requirements.

[Design records](docs/design/README.md) explain the rationale for individual
language features.
