# Building the Documentation Site

The generator follows PEGO's approach: a separate Go module uses Goldmark to
render repository Markdown and an HTML template. HFF's generator renders
`README.md`, `spec/**/*.md`, and `docs/**/*.md`, without modifying those sources.
It has no dependency on the PEGO checkout or a JavaScript build toolchain.

The website's public URL is [hff.ornew.net](https://hff.ornew.net/).

## Netlify deployment

The repository's [netlify.toml](https://github.com/ornew/hff/blob/main/netlify.toml) builds the site with
`sh site/build.sh` and publishes `site/dist/`. It pins Go 1.24.2, compatible
with the generator's Go module. Browser scripts and styles are served locally;
the configuration includes a Content Security Policy and response headers.

Connect the repository to Netlify, use `main` as the production branch, and
configure `hff.ornew.net` as the custom domain with its required DNS records.
Once configured, commits pushed to that branch trigger deployment. The domain
is documented here ahead of the first publication; a local build does not
configure Netlify or verify a production deployment.

## Build and preview

Use Go 1.24 or later, from the repository root:

```sh
sh site/build.sh
sh site/build.sh -serve localhost:8080
```

The first build needs the Goldmark module downloaded or available in the Go
module cache. Builds otherwise use local inputs. The second command builds,
then serves the generated site. Stop it with Ctrl-C. Re-run the command after
editing Markdown; the server does not automatically rebuild.

The output defaults to `site/dist/`. It is generated and ignored by Git. Open
`site/dist/index.html` directly or serve the directory with any static server.
Relative links support hosting the output beneath a URL subpath. Build commands
do not publish the site or provision hosting.

To select a different output directory:

```sh
sh site/build.sh -out /tmp/hff-site
```

The generator refuses source directories and unrelated nonempty directories.
A directory generated by HFF contains `.hff-site`; a subsequent build replaces
that output, including old pages. Do not store hand-written files in generated
output directories.

## Rendering and link checks

The site includes a README-derived landing page, top navigation, documentation
sidebar grouped into Language, Design Records, and Development,
heading links, adjacent-page links, and GitHub source links. Design Records and
Development use collapsible groups. Small
screens use a modal navigation drawer instead of a horizontally scrolling menu.
Color mode cycles between system, light, and dark, storing the choice locally.
Dark mode uses neutral near-black surfaces with green accents.
Markdown tables and fenced code blocks are rendered directly. Source Markdown
is the single authoring surface; generated HTML must not be edited.

Search runs locally over a generated `search-index.js`, including page text and
headings, with no remote service. Open it with the search button, `/`, or
Ctrl/Cmd-K. Arrow keys move between results, Enter opens a result, and Escape
closes the dialog. Search, theme controls, and the drawer use browser JavaScript;
the documentation itself remains static HTML. The script-based index also works
when HTML files are opened directly.

Repository Markdown links are rewritten to relative HTML links. Before writing
output, the generator rejects missing internal pages and heading fragments.
External URLs are preserved; their remote availability is not checked.
The license is copied into the output. Other local non-page assets are not yet
supported: use an external URL or extend the generator explicitly when needed.
Raw Markdown HTML is not enabled.

## Verification

From `site/`:

```sh
go test ./...
go vet ./...
```

Build the actual documentation as well as running tests. Tests cover link
rewriting and fragments, stale-output removal, and refusing unrelated output
directories. Build failures preserve existing output when source links are invalid.
